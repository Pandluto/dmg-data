# ADR-0001：来源锁与生成证据

**Status:** Accepted

## Context

AKE 表、运行时 JSON、Calc fixture 与审计数字会独立变化。把版本和统计手工复制到多份文档会产生无法判断来源的冲突，也无法证明目录中的数千个文件属于同一快照。

## Decision

公开输入以来源锁、语料 manifest、逐文件哈希和内容聚合哈希固定。当前目录规模、覆盖率与缺失依赖由确定性生成器从这些机器事实及审计 JSON 生成到单一证据页。架构、Spec、指南和研究只解释口径并链接证据，不维护第二份当前数字。

运行时语料同步默认使用已固定的本地资产索引；刷新上游 revision 必须显式请求。数据一致性检查重新读取实际文件并重建递归依赖闭包，不仅检查 manifest 自己是否能解析。

## Consequences

- 数据更新增加一个明确的锁重建和证据重生成步骤。
- 任意混版、漏同步、手改 JSON 或陈旧证据页会让基础验收失败。
- 相同输入可以确定性复现同一证据页和聚合哈希。
- 来源完整性仍不等于行为精确；oracle 和机制场景继续承担高层证明。
