## 先找对材料

本项目使用仓库内固定的公开 AKE JSON 与表快照。对话中的“解包数据”分析应落实到具体文件、字段和来源版本；当前材料并不等于已经掌握游戏全部私有实现。

完整查找路线以 [数据来源与派生链](../../architecture/data-lineage.md) 为准：角色技能组定位 SkillData，等级与潜能查 SkillPatch/相关效果表，再沿 Buff、能力实体、投射物和 child skill 递归。页面展示文本、raw 默认值与实际有效参数属于不同层。

## 这轮值得保留的判断

- **默认值不能替代调用上下文。** 汤汤水龙卷天赋 raw fallback 与满技能调用值不同；先保留等级、潜能和当前实例 Blackboard，再解释倍率。具体证据见 [汤汤](../operators/tangtang.md)。
- **序列化字段并不互斥。** Blackboard 条目可能同时包含 `valueDouble: 0` 与非空 `valueStr`；非空字符串必须保留为 ID/表达式，不能先取默认数字槽。汤汤法术脆弱的 `child_buff_id` 是真实反例。动态持续时间还要追到 `SaveBuffLifeTime` 的实例计时器，不能把未执行的赋值留下的 0 当成游戏规则。
- **字段必须到执行层仍有语义。** `switchToBuffConfig.asSkillCast`、`limitSkillCastId`、Channeling 的目标设置和 `DamageScaleProcessor` 都曾在转换中丢失。找到原始字段后继续查编译结果及真实事件，不能止于“文件里有”。
- **同一个派生程序内也要逐效果核对目标。** 别礼幻影曾出现伤害打敌、寒冷打自己的情况：DamageAction 保留了 `Context/tar`，SpellInfliction 却硬编码 `Target`。不能由伤害目标正确推断状态目标正确，也不能在没看 `targetId` 时把问题归因于跨来源聚合。
- **名字相同不代表身份相同。** 主控、施法者、来源实体、carrier、目标以及 root/child cast 分别追踪。限次作用域要核对原始规则；汤汤同次战技多龙卷就是多个实体执行 ID 共享一次施冷限额的反例，不能仅凭 child cast 不同推导各自限次。
- **时间必须带坐标系。** 整按钮显示偏移、原始技能 timelineFrame、全局帧与局部时钟不能互换；按真实事件和释放依赖核对。具体反例见 [别礼](../operators/lastrite.md)。
- **派生程序必须同时更新准入语义。** 卡缪强化战技执行 `CastSkill` 后，伤害已是连携程序而控制仍停留在原战技，会让后继过早中断。输入身份与实际程序的类型、优先级、占用和局部时钟要分别保留；见 [卡缪派生技能调查](../../maintenance/derived-cast-admission-20260905.md)。排轴持续排队也不同于单次按键的短缓存，不能混用。
- **数值正确也要追原因。** 总伤害相同可能掩盖少一击、多一击或错误来源抵消；日志、状态和逐 Hit 的第一处分歧更能定位问题。

## 可复用记录方式

昂贵分析完成时，为主题留下原始 ID/路径、字段或 JSON path、使用的等级/调用参数、执行证据、结论及仍不明白的分支。小型重放输入与源码定位应能脱离临时聊天找回；较大输出留 RIA，并在条目引用 Run。

数据/执行版本变化后先复查相关条目，涉及字段默认值、时序或事件过滤时尤其如此。与新证据冲突的结论标为待复核并保留旧来源；知识库不替运行时补猜缺失规则。
