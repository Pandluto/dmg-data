## 合并检查发现的读取写回缺口

实际调用 `loadTimelineData → ensureTimelineDataConsistency → getSkillButtonTable`，在内存存储中恢复带旧格式按钮的轴，仍出现一次 `def.skill-button.v1` 写入。最小复现只需一条使用受支持 `panelSnapshot` 字段的旧按钮，直接调用 repository 读取即可失败，排除了目录初始化和完整轴构造。

原因是上层已经取消保存，但底层 repository 和 storage compatibility 两个 `getSkillButtonTable` 仍会在格式补全后立即持久化。读取后底层写入的行为违背 ORDER-02 的“内存迁移，正常编辑／保存时才落库”。这不是顺序代码的文本冲突，而是原分支未覆盖的读取路径。

两个入口均保留原格式补全和返回值，只移除读取中的自动 `setItem`。显式 setter／编辑流程仍保存补全后的数据。新增 [读取纯度回归](../../../demo/lts-ui/src/core/repositories/skillButtonReadPurity.test.ts) 检查两个表读取与按 ID 读取、重复读取、旧 panel/Buff/时间戳保留及显式保存一次。修改前失败，修改后通过；原完整服务调用也由一次写入变为零次。
