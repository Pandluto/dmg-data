核验日期：2026-09-06；数据为当前 Chrome 的别礼/汤汤九动作轴，AKE 数据版本见运行归档。
本次知识内容提交及日期：见 [版本索引](../README.md#条目版本)。本文先记录原始证据，修复状态以 Spec 和实现提交为准。

## 结论

不能从一个状态事件的 `rootCastId` 就断言「该状态是这个技能提供的」。持续 Buff 可以由战技施加，随后由普攻命中触发，在更晚的帧数生效。效果来源、触发动作和生效帧需要分别保留。

已核验案例：别礼在 F50 普攻过程中使用战技，战技给予自身 Buff；重击在 F128 命中后触发，该 Buff 在 F137 使寒冷从 2 层变成 3 层。界面把三层寒冷放进 F0 的重击卡片，既混淆来源，也提前了显示时序。

## 可复用边界

展示层可读取显式因果链区分来源与触发，不能按角色名、最近按钮或颜色猜来源，也不能因此改写普攻的伤害结算身份。缺失链保留已知事实；循环和未来事件必须停止追溯。

消费事件及消费后触发的新效果要另外处理：`OnConsumeBuff` 的父事件可能是被消费的状态，不能穿过这个边界把消费者产生的新效果归给原附着提供者。定时到期也不是来源技能再次主动释放。

布局上，来源 ID 是语义事实，不能作为晚生效状态的起手位置。技能卡片和状态时间线的职责见 [状态来源与时序 Spec](../../specs/timeline-state-flow/spec.md)。
