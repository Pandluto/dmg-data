# 技能扣费、冷却归属与独立叠层修复 Spec

## Status

**Status:** Accepted

**Implementation:** Not started

**Updated:** 2026-09-12

**Scope:** 修复自主探索确认的三项通用机制错误，以小规模、有判别力的验证交付。

用户已授权按 spec + tasks 实施并转交既有独立任务，明确要求测试不要多，能够证明问题修复即可。执行责任、固定起点、证据位置和进度见 [任务表](tasks.md)。Accepted 表示需求已接受，不表示实现或验收完成。

## Problem Statement

真实角色、武器与排轴组合暴露三处规则断裂：

1. 莱万汀成功施放终结技并扣费后，熔铸火焰依赖 `OnAfterSkillApplyCost` 的普攻增益没有创建。排轴直接修改资源，绕过带有事件通知的资源事务。
2. 莱万汀终结技结束动作后输入强化普攻，被终结技冷却拒绝。装配把目录归组当作冷却归属，覆盖了实际程序的普通攻击身份。
3. 秋栗通过技能多次回复技力，触发 O.B.J.轻芒叠层；新层刷新整组到期时间，旧层未按说明独立到期，进而多算伤害。

这些问题分别涉及入口一致性、身份解释和状态寿命。已有原语和静态登记不能保证完整行为。本轮修复进入通用实现，不为三个样本添加角色专用捷径。

## Solution

在现有结构上收拢技能扣费事务，明确冷却归属与实际执行身份，为有来源证明的独立叠层保留逐层寿命。仍由 runner 调度输入、runtime 执行战斗事务、状态机维护状态；不合并成新的万能引擎。

直接复用已经保存的最小输入证明原版失败，再逐项修复并确认相同输入通过。完整配装各重放一次，核对对应机制；测试通过且无新增疑点后停止。

## User Stories

1. 作为排轴用户，我希望符合武器条件的成功施法实际触发对应增益，资源账本、事件与属性来源能互相对应。
2. 作为排轴用户，我希望终结技形态中的普通攻击按其真实规则执行，不被技能目录分类错误拦截。
3. 作为排轴用户，我希望声明独立计时的 Buff 层按各自获得时间到期，伤害只计算仍有效的层。
4. 作为维护者，我希望这次修复覆盖相同语义的调用入口，并以少量明确的证据完成验收。

## Requirements

### Requirement COST-01: 技能扣费通过统一战斗事务

系统 SHALL 为技能扣费提供统一的 runtime 操作，在一次调用内保留资源变更、实际施法身份与对应事件通知。通用单人、小队、派生和替代施法的实际扣费都必须进入该操作，不在每个调用者分别拼接补发事件。

#### Scenario: 熔铸火焰在终结技扣费后触发

- GIVEN 已保存的莱万汀单人最小输入，装备熔铸火焰、无装备、资源满足终结技消耗
- WHEN F0 终结技成功施放并实际扣费
- THEN 产生对应 `OnAfterSkillApplyCost`，携带本次技能、施法和角色身份
- AND `buff_wpn_sword_0006_valid` 按有效参数创建，普攻伤害增益为 +120%、持续 20 秒
- AND 同一次扣费不会因 runner 和 runtime 都发通知而重复触发

#### Scenario: 不发生实际技能扣费

- WHEN 准入失败、资源不足或派生操作明确跳过扣费
- THEN 不生成虚假的扣费通知或额外消耗
- AND 零消耗、非技能资源变更保留已确认语义，不根据武器名称推定新规则

### Requirement IDENTITY-01: 冷却归属与目录位置分开

系统 SHALL 区分输入按键、实际技能类型、目录分组和冷却归属。目录位置不能无条件覆盖原始技能身份；需要共享冷却的程序仍须依据明确规则共享。

#### Scenario: 开大后的强化普攻可执行

- GIVEN 莱万汀单人基础武器最小输入，F0 开大，普攻依赖终结技动作结束 +1 帧
- WHEN 该普攻依赖解析到 F75
- THEN 以实际强化普攻程序成功执行并产生正常命中，不因终结技组冷却被拒绝
- AND 执行与结算身份保留普通攻击语义

#### Scenario: 合法共享冷却仍然生效

- GIVEN 已确认需要共享冷却的基础与强化连携程序
- WHEN 同组冷却尚未结束
- THEN 两个程序继续读取同一份冷却
- AND 不以“所有派生技能独立冷却”或“只看程序自身冷却为零”解决强化普攻问题

### Requirement STACK-01: 已确认独立寿命的层分别到期

系统 SHALL 显式表达叠加与寿命策略。对于来源确认每层独立计时的效果，每次获得的有效层都有自己的寿命；新增层不延长旧层，单层到期只移除该层贡献。汇总层数、属性来源与伤害计算必须消费相同的有效状态。

#### Scenario: O.B.J.轻芒旧层按时消失

- GIVEN 最终单人最小输入：秋栗自身战技后按动作结束 +1 帧开大，实际终结技执行于 F41
- WHEN F101、F128、F161 三次真实回复分别获得一层、每层持续 600 帧
- THEN 三层分别在 F701、F728、F761 到期；相应到期处理后剩余层数为 2、1、0
- AND 每层火/电伤增益按有效参数 +8.4% 汇总，到期后不再保留该层属性贡献
- AND 生命周期记录能区分单层到期与整个效果结束

#### Scenario: 其他寿命策略保留自身含义

- GIVEN 来源定义为整体刷新或独立多实例的其他状态
- WHEN 重复施加
- THEN 继续按其声明的策略处理，不能把所有可叠层 Buff 一律改成独立到期
- AND 达到上限后的替换规则、消费顺序等证据不足部分不得由一个武器样本推定为整个枚举的规则

### Requirement EVIDENCE-01: 修复证据来自原输入与运行事实

系统 SHALL 在真实 `simulateSquadDemo` 入口使用既有输入验证三个问题；预期来自本 Spec 和固定来源，不能读取修复后输出生成预期，也不能只检查总伤害变化。

#### Scenario: 原版到修复版的可判别验证

- WHEN 迁入三个最小输入并运行
- THEN 原版在对应行为断言失败，修复版通过
- AND 不更改输入前置、潜能或时间来避开缺陷
- AND 原始 RIA、fixture 和旧版结果保持不变；修复版证据写到新的交付位置

## Implementation Decisions

- 沿用已有 compiler、runtime、资源和状态模块。技能扣费增加或提炼有完整语义的接口，并梳理四类调用入口；不要暴露私有通知方法让调用者继续手动配对。
- 冷却绑定保留来源解释。输入种类、实际执行类型、冷却所有者各自明确；不新增角色 ID、展示名或 fixture ID 判断。
- 寿命策略作为类型化定义传到通用状态机。原始枚举不足以说明独立计时时，可以在既有语义映射中加入带具体来源的声明；通用代码不通过武器/Buff ID 分支实现例外，也不在运行时解析中文描述决定规则。
- 独立层数据应能支持当前已有的到期、清除、消费和时钟操作，避免新计时器在实例结束后重新产生贡献。仅实现本轮实际涉及和已有接口必须维持的行为，不顺带扩展未知机制。
- RIA 和报表继续观察真实状态。不得在记录器、投影或前端合成缺失 Buff 或修正数值。
- 事件登记不等于所有入口验证完成。本轮不重构整个审计体系；只同步受本次实现实际影响的声明、文档和派生产物，已知旧基线问题单列。
- 与 [排轴执行顺序 Spec](../timeline-execution-order/spec.md) 并行。不得改其输入版本、排序、控制权或依赖调度合同；最终若有文件合并，分别保留两项需求。

## Testing Decisions

本轮采用用户要求的最小验证范围。既有 `simulateSquadDemo` 是三个真实复现共同的测试入口；必要的通用资源/状态合同使用现有公开接口，不测私有方法。

| 验收项 | 最小证据 |
|---|---|
| AC-01 扣费通知与武器增益 | 原最小输入修复前失败、修复后通过，检查实际扣费、一次通知、Buff 及参数 |
| AC-02 强化普攻 | 原最小输入修复前失败、修复后成功命中，实际身份正确 |
| AC-03 独立层到期 | 原最小输入一次执行，检查三个到期点和属性贡献；不要为每一帧重跑模拟 |
| AC-04 同类入口与关键反例 | 一项小型扣费事务正负对照；复用已有合法共享冷却测试；一项整体刷新与独立到期的寿命对照 |
| AC-05 完整配置仍成立 | 三份已保存完整输入各重放一次，只检查对应缺陷行为与新诊断，不冻结整轴伤害快照 |
| AC-06 交付可追溯 | 记录基线/修复提交、命令、结果、必要诊断和范围；文档结构/链接检查 |

**预算与停止条件：** 三个主要失败回归；最多补两项短通用行为对照；共享冷却优先复用既有用例。完整输入仅各一次。不得重新运行 141 输入探索、全角色矩阵、全仓测试、前端全套、浏览器 E2E、性能或压力测试。检查通过即收口；只有具体的新失败或未决风险才扩大到对应的最小范围，并在任务记录说明原因。不能通过把大矩阵藏进一个测试函数规避这个限制。

本轮不修改前端，无须启动、刷新或自动运行浏览器/开发服务。截图是可选证据；环境不可用或被占用时记录跳过，不让截图阻塞机制修复。不修改原始外部数据，不重新抓取游戏或 Calc。

## Out of Scope

- 大规模重构整个引擎、事件审计分级平台或新的自动搜索系统。
- 补齐所有未支持连携、空间/实体命中、概率、敌方 AI 或其他探索候选。
- 数据版本升级、解包新游戏资源、重抓全套外部 oracle。
- 前端布局、主控预演、像素与逻辑序迁移、存档格式。
- 推送、部署、修改用户活动轴或原始 RIA 档案。

## Further Notes

来源与原始复现的本机路径、最小输入时间、完整数值样本时间分别记录在 tasks 中。单人轻芒的首处分歧是 F701；完整队伍样本的首处分歧是 F778，不能混用。

此前观察到的单次伤害差异用于证明旧层滞留的影响，不作为三个修复同时落地后的整轴固定答案。验收应检查相应命中的有效层贡献及原始因素。

开发原则继续遵守 [来源驱动的通用语义](../../architecture/decisions/0004-source-backed-runtime-semantics.md) 与 [RIA 观察事实](../../architecture/decisions/0003-ria-observes-runtime-facts.md)。具体执行清单见 [tasks](tasks.md)。
