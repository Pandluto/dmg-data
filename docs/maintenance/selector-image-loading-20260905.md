# 配置选择器图片加载优化

2026-09-05，在用户当前 Chrome 的 `#/timeline/operator-config` 页面调查；
角色洛茜、武器狼之绯，90% 缩放、设备像素比 1.8。通过 RIA 实时接口读取
真实图片地址/资源耗时，并操作同一个 Chrome 验证打开、重开和滚动。

## 原因与修复

选择器使用 AKE 站外原始 PNG。多数武器/装备源图为 256×256、262,604 字节；
头像 200×200、160,336 字节。列表中武器图片实际仅约 63×63 CSS px。
目录数据已有缓存，当前调查没有证据表明每次打开都在重复解析整个目录。

461 张有效目录图片打包为同源 WebP：原尺寸共 12,617,546 字节，
对应 PNG 为 96,311,070 字节；额外 363 张 128px 缩略图共 4,710,952 字节。
原尺寸无损，缩略图用于小图显示，浏览器按像素密度选择。
武器、装备、选人列表共享可见时加载、异步解码与已加载资源复用；
武器/装备入口最多预热前 12 项。哈希资源有一年 immutable 缓存及 ETag。

Chrome 验收还发现重复解析把新哈希 URL 模糊匹配回旧 PNG。
现将官方 URL 和已解析的哈希 URL 在历史模糊匹配之前解析，保持多次解析一致。
完整资源校验账本只用于生成流程，浏览器映射去除下载字节数和 SHA 元数据；
对应 web-app 构建块由中间实现的 347.32 KB 降到 225.94 KB（gzip 89.15 → 38.11 KB）。

## 实际结果

| 场景 | 调整前 | 调整后 |
| --- | --- | --- |
| 当前武器弹窗及背景角色/武器，22 个实际唯一图片 URL | 5,572,752 B | 270,248 B，减少 95.15% |
| 同一界面前 8 张图片 HTTP 实际文件体积 | 1,896,296 B；最大 262,604 B | 135,442 B；全部低于 50 KB |
| 这次 Chrome 新武器图片请求 | 基线为已热缓存的页面，未记录可比的冷浏览器请求 | 2–12 ms |
| 武器弹窗点击到两次 animation frame | 未记录可比基线 | 首次 25 ms；重开 18 ms，无新增图片请求 |
| 64 件护甲首次打开 | 普通 img 全部设置 src | 27 张请求，37 张 deferred |

原始 8 张 PNG 独立冷 HTTP 探测为 105–185 ms，新同源图标 HTTP 探测最大 2.69 ms。
这些是本机当次网络观测，不能当作线上或弱网下的固定耗时；
点击绘制耗时也不等于全部异步图片完成时间。

滚动护甲列表中段后新增图片正常解码；到末尾时最后 5 项全部加载并可见，
截图核对图形、透明背景和名称正常。快速跨过的 4 项仍 deferred，不强制整表下载。
没有更换用户角色、武器或装备。

## 验证与再次调查

- 在当前 Chrome 真正打开列表后，用 `GET /api/ria/live/sessions` 查当前 Session，
  再取 `snapshot?section=ui`。按 `images[].src` 请求文件并断言实际字节数；
  本次相同的 50 KB 探测对原先前 8 张图失败、对优化后前 8 张图通过。
- 通过 `events?kind=network&limit=200` 检查 ImageResourceLoaded；
  通过 `events?kind=state&limit=200` 检查 InteractionPainted/主线程长任务。
  重开不能增加图片传输，滚动必须让新进入可见区域的图片解码完成。
- 武器、头像、装备各抽样一张，对原始 PNG 与原尺寸 WebP 比较 alpha 及非透明 RGB，完全相同。
- 全部 824 个构建图片与校验账本 SHA-256 一致；构建服务器实际 HTTP 验证 GET、
  HEAD、ETag 304、缺失图片 404 和 immutable 响应。
- TypeScript 类型检查、已有图片路径兼容/对象 URL 稳定性检查、Demo 构建通过。
