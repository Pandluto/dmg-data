# 破防与火附着标识避让

分析基线：`4e69f72`，2026-09-06。证据采集日期：2026-09-06。
本次布局算法、回归与规格的提交见本文件 `git log -1`；React 接入及主题层级修正保留在既有 UI 工作区，未夹带之前的引擎和存档改动提交。
规格：[STATE-01](../../../specs/timeline-release-lens/spec.md)。现场：[browser-evidence.json](browser-evidence.json)。

## 现场与原因

用户原 Chrome 中的洛茜/卡缪排轴存在两种冲突：

- F148 同时发生灼热附着 1→0、破防 1→2、破防 2→3。原 `slot * 17px` 纵向堆叠没有申请行高，第三项和下一位角色起手说明重叠约 34.64×13.99px。
- F541 火附着叠层与 F748 破防到期被长尾投影压到相近横坐标，原代码只按相同帧分槽，两标签重叠约 21.57×16px。
- 原液态主题还给 grid shell 单独设定 z-index:2，状态控件困在该层内，无法越过外面的技能按钮。第一次原生点击没有命中状态；纠正主题层级后再次点击命中预期命令。

## 修复

在每个角色行内按投影位置处理冲突事件组，横向排列并保留原 frame/sequence。用引线指向真实时刻，标签避让不写入排轴；超过 180px 的密集组使用计数入口，展开仍有全部原始事件。没有将消费、重新施加或连续叠层抵消/合并成新的战斗事实，也没有扩大画布格子。

## 验证

- 通过 RIA `ui.controls` 的真实 DOM 边界比较，修复前两项冲突为失败，修复后原 11 个主轴状态标签相互之间及与起手说明之间均无矩形重叠。
- 原 Chrome 可见检查确认 F148 三项横排，F541/F748 两项横向避让；原生点击破防 F148 的 1→2 记录后，inspection.selectedCommandId 为预期的 `j1xnfsn7v`。沿用查看关联动作的行为，没有宣称检查器已自动定位到该事件帧。
- 修复前后执行输入、配装和 mainTimelineStateEvents 完全一致，总伤害均为 118173.72537302248。未保存或覆盖命名存档。
- 前端类型检查、构建通过。`stateMarkerLayout.test.ts` 覆盖原现场的两种碰撞、页边界、密集组、空输入，并检查原事件完整保留。
- 密集组的展开入口已实现，但本次原浏览器是稀疏实例，没有为演示而修改用户轴；密集弹层的原生鼠标/键盘验收仍留在任务 S-05。
