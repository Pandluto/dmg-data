## Problem Statement

状态的效果来源、触发动作、生效时刻是三个不同事实。旧投影直接使用施放 ID，把战技 Buff 在后续普攻触发的寒冷归给普攻；普通模式又将圆标限定在来源按钮的起手框内，阅读模式则将后续状态压回起手卡片，造成归属和时序双重误读。

当前九动作轴中，别礼 F50 战技施加自身 Buff，普攻命中后在 F137 触发寒冷 2→3。因果链为 status-event:245 → 243 → 53，53 是战技 Buff。F137 必须保留，效果来源为战技、触发为普攻；不能把整个普攻的伤害结算身份改成战技。

## Solution

技能框只表示动作及其名称，状态仍独立渲染。普通模式保留已有「轴底真实时间点向上引线」的表达：底端永远固定在事件生效帧的投影位置，上端优先垂直放置圆标；只有该横坐标所有可用高度都被遮挡时，才由近到远向左寻找空白。

避让以事件时间为基准，不能用来源技能的起手框限定位置，也不能把圆标重新挂在附近某个按钮上。来源、触发与生效帧在详情中分别说明。左移保持局部范围和事件先后；空间完全不足时保留明确的多记录摘要，不能丢弃事件或偷偷归入无关技能。

阅读模式是同一布局的简化绘制：复用普通模式求出的圆标水平位置，隐藏时间、命中及引线等细节，技能仍使用原位置的白色圆角卡片。不新增专用状态行，不因为普通障碍被隐藏而重新排圆标。直接进入阅读模式及在阅读模式内批量删除后，也必须基于最新普通模式几何得到相同布局。

## User Stories

1. 用户能看出战技赋予的效果在后续普攻触发，并在实际生效位置看到附着增加。
2. 用户打开阅读模式，仍能沿排轴读出 1→2→3→4→消费的顺序，技能名称与状态分别显示。
3. 用户查看状态详情，可区分效果来源、触发动作与帧数；未知来源保持未知，不靠最近的技能猜测。

## Requirements

- 来源追溯只使用显式因果 ID，区分消费者与被消费状态的来源；处理缺失链与循环，不使用角色名特判。
- 普通与阅读视图共用状态事件、真实帧及同帧事务顺序；切换模式不改输入、命中、状态结算或伤害。
- 阅读技能卡不再包含最终附着摘要；保留技能矩形、名称、角色、分组、技力与能量。
- 保留已有 20px 图标、双黑框、窄白环、白色图案阴影及黑色粗体层数。表示消费的 × 保留。
- 持续语义按 scope/buff 的共同状态池确定下一变化，不按来源动作截成虚假的独立状态；不另增贯穿上方的持续条。原始事件和详情保留先后、消费和已知到期边界，未观测到自然终止时不能宣称永久持续。
- 普通布局先穷尽真实 x 的合法纵向位置（先保留舒适留白，再考虑实际矩形不相交的紧凑槽），再按左移距离递增寻找；不用加权打分让横移胜过可用垂直位置。向左搜索保持本组角色内容边界和同一行事件顺序；不以固定留白或任意半格上限把本可展示的单个状态折成「+1」。
- 阅读模式复用普通布局的横坐标和聚合结果；若技能矩形遮挡，只允许固定 x 后上下避让。不能使用阅读障碍集重新求 x，也不能依赖进入阅读前曾经打开过普通模式。
- 状态数据属性暴露事件键、帧、来源命令与触发命令，便于 RIA/DOM 联合检查。
- 批量选择仅针对技能卡，独立状态不能成为可删除的操作。

## Implementation Decisions

- `akeRuntimeLedger` 构建来源/触发分离的只读状态事件；原始运行结果不改写。
- `TimelineStateMarkers` 与画布时间投影负责两种模式的独立状态层；技能按钮负责自己的矩形和名称。
- 状态布局以事件时间坐标为约束，移除将晚生效事件锁回来源 80px 起手框的行为。普通模式恢复底部真实帧锚点与向上引线；模式仅决定细节是否绘制。
- 普通技能与投影测量结构在阅读模式仍保留尺寸，以明确的仅绘制隐藏和交互禁用区分真正不存在的元素；不复制画布或临时切换可见模式。
- 2026-09-06 用户纠正：先前独立上方状态带、短水平连接及阅读模式单独重排方案已撤销；保留来源修复。

## Testing Decisions

冻结当前 Chrome 工作区与运行结果，使用真实 F137 因果链核对效果来源和触发；完整应用隔离 Chrome 比对两种模式的事件帧、每个事件的相同水平位置、独立 DOM、普通模式底部引线与直接阅读初始化；布局样例只验证垂直优先、挡住后向左和不丢记录。保留必要的通用因果链及布局回归，不改写用户轴。

## Out of Scope

重排用户输入、改角色伤害机制、手机版、改图标配色、推送与部署。
