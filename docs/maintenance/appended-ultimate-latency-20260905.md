# 追加洛茜终结技改变连击层数与交互重算卡顿

问题来自 Chrome 的实际八节点轴，通过 live debug snapshot、请求体和对应 Run 定位。
此前只检查固定输入，没有覆盖追加后继节点的前缀一致性和端到端耗时，遗漏了真实编辑路径。

## 实际原因

- 前端保存了“卡缪 E 最后一击后 6 帧”的关系，Provider 却只提交旧预演帧 F369。
  卡缪强化 B 经实际派生施法准入后，E 在 F380 开始、F427 完成最后一击。
  提前在 F369 释放的洛茜 Q 先消费第一层，并暂停其他角色的技能时钟，
  后续 E 的连击积累因此发生在消费之后。
- 同输入重复执行稳定，没有发现历史伤害随机重算；追加命令丢失了真实时序关系。
- 每次自动记录创建新 Worker，重复加载和编译数据约 7 秒。
  持久化事件背压和封存等待也进入了交互结果的关键路径。
- 画布继续使用旧预演起止帧，即便报告中实际帧已改变，显示仍与结算不一致。

## 修复

保留命中释放依赖，实际 HP 命中驱动后继输入；未到达命中明确失败，不回退旧时间。
报告投影更新画布坐标，同时保留独立输入计划，避免显示变化触发计算反馈。
原始锚点关系加入 execution digest，过期和取消请求不得发布报告或覆盖当前调试状态。

自动记录复用预热的编译数据，每次建立独立战斗运行时。结果先交付，真实事件随后后台
归档；缓冲窗口满时恢复持久化背压。显式记录和回放保留原有流式持久化语义。
文件描述符复用仅应用于自动 UI 归档；普通归档保持逐次关闭，以兼容 macOS 跨进程目录监视。

## 验证边界

原七节点轴与追加轴在 F433 前的完整伤害及连击记录一致；来源命中不存在时后继失败。
复用 Worker 连续运行结果一致；人为阻塞归档 drain 时仍能获得浏览器结果，最终两次归档
事件数量一致且没有丢失。相关运行时回放、SSE、前端时序检查通过。

现有 `COMBO_TRIGGER_UNVERIFIED` 仍表示触发条件未完全验证；本次修复不能据此声称所有
角色触发规则或所有控制模块均已验证。
