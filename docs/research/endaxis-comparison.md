# Endaxis 对照结论

## 研究定位

本项目在固定提交 `66bb80be8c07bf8b27c2606c220836f5537bf664` 上研究 Endaxis。它是机制覆盖、事件模拟和编辑器能力的成熟对照，不是 AKE/Calc 数值权威，也不是本仓库的新底座。

三套项目各自承担不同责任：

| 项目 | 最值得保留的责任 |
| --- | --- |
| `dmg-end-field` | 产品外壳、配置工作流、伤害解释体验和文档纪律 |
| `ake-calc-cleanroom` | 来源证据链、严格指令合法性、通用运行时、真实 Hit 与共享变速时间轴 |
| Endaxis | 机制目录、类型化战斗 DSL、事件队列、读取模型和测试维度参考 |

## 值得吸收

### 稳定的规范化战斗语言

角色、武器和装备差异应编译为少量通用原语：状态事务、事件订阅、条件代数、派生 Hit、资源、冷却、窗口、形态、目标作用域和 patch。角色名词留在数据层，核心只理解原语。

### 确定性事件队列

动作开始、Hit、状态消费、资源和清理必须按统一顺序执行。每个事件保留来源、目标、技能、cast 与父子关系，才能解释额外 Hit 和状态归属。

### 一份事实，多种投影

伤害详情、资源曲线、状态条、连携窗口和战斗日志应从同一份模拟账本生成，不由各组件重复推演。这一原则已经进入本项目的 report、timeline projector 和 runtime ledger。

### 结构化伤害明细

结果不只返回总伤害，还应保存每个乘区、操作数、贡献来源和乘积校验。具体术语与方向仍由 AKE 数据、Calc fixture 和本项目公式决定。

### 全语料扫描与角色场景并存

全语料 audit 发现结构缺口，角色场景证明组合行为。两者不能互相替代：覆盖率很高时，一个关键状态消费或事件生产者仍可能让角色机制失真。

## 不应照搬

| Endaxis 做法 | 本项目的处置 |
| --- | --- |
| 固定秒/帧的线性视觉轴 | 保留真实帧权威，使用共享变速投影和强边界分组 |
| 条件不满足仍继续模拟的诊断式合法性 | 指令、资源、冷却和窗口按领域规则 fail closed |
| 人工 TypeScript 定义作为主要事实源 | 保留公开原始 JSON、来源锁、语义映射、fixture 和 unresolved |
| 大型 store/组件承载模拟与交互 | 运行时、投影、provider、ledger 与 React 展示分层 |
| 角色 ID 特例渗入核心与组件 | 角色差异编译成通用原语，UI 只读语义化结果 |
| 固定 60 FPS 语义 | 本项目使用 30 tick/秒的运行时口径 |

研究提交未发现可供本项目复制实现的许可证文件。因此这里保留可独立实现的思想、验证维度和观察结论，不复制其源码或手工数据表。

## 对当前架构的影响

Endaxis 研究促成了五层结构：证据、规范化、运行时、投影和产品外壳；也强化了三项约束：UI 不重算、状态有来源、全角色“能执行”不等于“正确”。
