# 排轴状态来源与时序 Spec

## Status

**Status:** Implemented; current Chrome case verified

**Updated:** 2026-09-06

**Baseline:** `22cafe0`（2026-09-06）；来源语义修复为 `16a1cc2`。固定行与归属槽实现为 `9d55b6d`，最终直斜线样式为 `680c0c8`（均为 2026-09-06）。

**Scope:** 桌面普通视图、阅读视图的附着与破防圆标，包含施加、叠层、刷新、消耗和到期。

## Problem Statement

上一版错误地把高度作为自由避让空间：普通模式一冰、四冰落到轴底，二冰、三冰在上方；阅读模式又只挪动与技能卡相交的圆标，消费 × 留在另一个高度。虽然没有矩形相交，整套状态表达已经不一致。

另一错误是把「真实生效帧」当作上方圆标唯一横坐标，忽略上方图标需要表达谁提供/消费了状态。汤汤二冰由第二次战技带来，不应放在它前面的连携旁边。

## Solution

采用**固定高度的归属排布 + 保留真实时间的引线底端**。

普通模式：同一角色的所有状态在技能图标右侧的固定高度。先确定负责本次变化的动作，在该动作可见图标和类型文字的右边申请状态槽；仅沿水平方向避让。引线用一条直斜线连接真实生效帧的轴底位置与圆标下缘；找位顺序不决定线条路径。上方是归属顺序，下方是实际时间，不混为同一坐标。

阅读模式：沿用普通模式的全部横坐标，所有状态统一移到白色技能卡外的下方同一行。施加、叠层和消费 × 必须一起移动，不按单个图标是否碰撞来改变高度。隐藏引线、时间和命中细节，保留技能卡、角色、分组框、技力和能量。

## User Stories

1. 一冰出现在汤汤第一战技右上方，二冰出现在第二战技右上方；同刻相邻的连携不能夺走归属。
2. 别礼战技提供、普攻触发的三冰仍对应战技；其延迟到 F137 生效由引线底端和详情说明。
3. 别礼连携消耗四冰后的 × 跟随该连携；打开阅读模式后，它和所有附着数字都在同一状态行。

## Requirements

- 普通圆标 top 固定为角色起手行底部 + 2px；禁止上下搜索或挪到命中/能量基线附近。
- 阅读圆标 top 固定为普通状态区底部 - 23px，所有状态类型一致。当前格子中对应角色区相对 top 52px，白色卡片下方留 4px。
- 圆标继续为 20px、双黑框、窄白环、原元素色、大白图案阴影、黑色粗体数字。布局改动不重做图标样式。
- 负责动作取状态事件的 `commandId`：施加/刷新时是效果提供者，消费时是消费者。`sourceCommandId` 保留原效果来源，不能拿旧提供者替代消费者。
- 普通隐藏测量结构提供负责动作的可见图标/类型文字右缘，圆标从右缘 + 4px 开始申请位置。同一角色的状态按事件帧、同帧 sequence 排序，已放置的圆标作为后续横向边界。
- 只把与固定状态行实际相交的元素视作障碍。起手专行的额外留白不能占用状态行，否则会把图标错误推到后一个技能。
- 横向空位不能越过后续动作的可见图标左缘。确实放不下时使用明确的拥挤记录入口，保留全部事件；不得把状态假装成后续技能的角标。
- 同帧、同负责动作的附着与破防可以紧邻排列；不同来源的事务不能因同帧而丢失归属。
- 未知负责动作保持未知，保留真实时间锚点，不猜最近技能。
- 切换阅读只改变统一的显示高度及细节可见性，不另算横向位置。直接进入阅读、阅读中删除后重新计算也使用相同测量结构。
- 实际生效帧、依赖、命中、伤害与存档输入不变。批量选择仍只选择技能卡，状态圆标不是可删除动作。

## Implementation Decisions

- `akeRuntimeLedger` 继续沿显式因果链分离提供者、触发者、消费者和生效帧，不改写原始运行结果。
- `TimelineStateMarkers` 测量普通技能图标与文字右缘、下一个动作左缘；阅读仍保留普通 DOM 测量结构。
- `layoutStateMarkers` 只做固定高度的横向分配；移除纵向空位搜索、向左扫描及单个阅读圆标上下避让。
- 全部阅读状态统一变更 top；技能矩形与状态仍独立渲染。引线直接用直斜线连接真实帧底端与圆标下缘，不画先竖直再水平的折线；固定高度和横向找位规则不变。
- `stateMarkerIntervals` 保留共同状态池的变化/消费边界，供调试观察；不通过改变图标位置修改状态寿命。

## Testing Decisions

冻结当前 Chrome 九动作轴。完整应用隔离 Chrome 核对固定高度、提供/消费动作的右侧归属、普通/阅读共用 x、阅读冷启动与阅读批量删除后的更新。可见用户 Chrome 逐项核对一冰、二冰、三冰、四冰与 ×，比较输入与伤害未变。

保留固定高度、横向障碍、起手专行不占位、相邻动作边界、消费归属和事件完整性的少量回归；删除验证旧错误布局的断言。

## Out of Scope

改变伤害机制、重排用户输入、扩大格子、手机版、推送与部署。
